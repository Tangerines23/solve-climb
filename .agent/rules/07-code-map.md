# 코드 맵(Code Map) 규칙

에이전트(AI)는 이 워크스페이스에서 작업을 수행할 때 소스 코드의 효율적 탐색과 토큰 절약을 위해 다음 규칙을 철저히 준수해야 합니다.

## 1. 코드 맵 우선 참조 (Map-First Approach)
- **원칙:** 새로운 기능 개발, 디버깅, 또는 리팩토링 작업을 시작하기 전에 반드시 **`.agent/.code-map.yaml`** 또는 **`docs/.code-map.yaml`** 파일을 가장 먼저 읽어야 합니다.
- **목적:** 
  - 불필요하게 많은 소스 코드 파일을 직접 로드하여 컨텍스트를 오염시키는 것을 방지합니다.
  - 관련 파일과 함수, 상태(State)의 위치를 사전에 탐색하고 작업 대상을 정확히 좁혀서 분석합니다.

## 2. 맵 활용 워크플로우
1. 사용자가 변경을 요청하면 `.agent/.code-map.yaml` 또는 `docs/.code-map.yaml`을 검색하여 관련 컴포넌트, 서비스 함수, 상태 저장소의 이름을 찾습니다.
2. 맵 데이터에 명시된 `imports`, `calls`, `listens`, `emits` 정보를 바탕으로 로직의 전후 영향도를 평가합니다.
3. 수정이 필요한 파일(최대 2~3개)로 한정하여 해당 원본 코드 파일의 본문만 직접 열어 세부 구현을 확인하고 수정 작업을 수행합니다.

## 3. 가상 연결선(어노테이션) 작성
- 정적 분석으로 추적하기 힘든 동적 콜백, 이벤트 버스 통신, 혹은 간접 호출이 발생할 때는 주석 상단에 다음 어노테이션 태그를 작성하여 맵에 반영합니다.
  - `@calls <대상_파일_경로#함수명>`
  - `@listens <이벤트명>`
  - `@emits <이벤트명>`
- **예시:**
  ```typescript
  /**
   * @calls src/services/auth.ts#login
   * @emits loginSuccess
   */
  ```

## 4. 맵 최신화 유지
- 코드를 변경하거나 파일을 생성/삭제한 후 커밋하기 전에 반드시 `npm run build:map`을 실행하여 코드 지도를 갱신해야 합니다. (이 작업은 Husky pre-commit hook에 의해 커밋 시 자동 실행되나, 작업 도중 AI가 최신 상태의 맵을 필요로 할 때는 수동으로 빌드할 수 있습니다.)
